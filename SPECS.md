## 0.7.0: Agent Long-Term Memory
Porygon can now remember things about you across sessions through a file-backed long-term memory stored in plugin settings. A new **Memories** textarea under the Personalization section holds entries in `[id] YYYY-MM-DD HH:mm [importance] content` format wrapped in `<memories>` tags, sorted by importance (high, medium, low) and recency. The current memory block is injected into the system prompt on every turn (capped at the top 50 entries) so Porygon can recall durable context without resending raw chat history, and a new `<context>` block surfaces the current datetime, IANA timezone, and operating system to the agent. A single `save_memory` agent tool lets Porygon append a short, concrete memory (auto-generated 8-character id and timestamp), replace an existing one by passing its id with new content, or delete it by passing its id with empty content; saves are silent and do not interrupt the conversation. Memories are treated as fallible records, with the most recent entry preferred when conflicts arise, and the textarea remains fully user-editable so you can curate or wipe what Porygon remembers. The legacy `current_timestamp` tool is removed since the same information now lives in the system prompt context block.

## 0.6.1: QoL improvements
Porygon's chat now communicates its state more honestly. While the agent is working, a subtle loading indicator at the top of the panel makes it clear whether it's your turn or Porygon's. The placeholder bubble shown right after you hit send is renamed from `Thinking...` to `Connecting...`, since the agent hasn't actually started thinking yet. The tool-usage panel is leaner too: each entry now shows just the intent, dropping the redundant tool name so the list reads like a clean activity log.

## 0.6.0: Ask before guessing, approve before changing
Porygon can now pause mid-task and ask you a focused question when it genuinely needs your input, instead of guessing or producing a half-relevant answer. A small popover appears in the chat composer with the question and 2–4 short options; you can click an option, pick one with number keys or arrow keys plus Enter, type a free-form reply, or press Escape to let Porygon continue on its own. Once you answer, Porygon resumes exactly where it left off.

The same pause-and-ask flow also gates destructive vault actions: creating a folder, creating or editing a note, and renaming or moving files now prompt for **Approve** or **Deny**, and you can type a short free-form reason to deny with feedback so Porygon adjusts its next step. A new **YOLO mode** setting auto-approves these prompts when you want Porygon to move without interruptions, and the setting is read live so you can toggle it mid-conversation.

The `list` tool now returns folders alongside notes, so Porygon can find and act on folders by name. The selected option in the prompt uses your theme's accent color for clear contrast on both light and dark themes.

## 0.5.0: Persistent agent memory and Obsidian-native session metadata
Porygon now uses a LangGraph `MemorySaver` checkpointer keyed by a per-session UUID so the agent remembers prior turns within a session without resending full history each call. Saved sessions store their metadata as Obsidian-native YAML frontmatter (`id`, `title`, and a flat `mentions:` list of vault paths) instead of a custom comment block, making it queryable through the Properties panel, Dataview, and Bases; on load, mentioned notes and folders are auto-resolved from their paths and re-injected as file context. **Breaking change:** session files saved before 0.5.0 (custom `%%porygon:metadata%%` blocks and timestamp-based filenames) are no longer readable — start fresh or migrate manually.

## 0.4.0: Agent skills loaded on demand
Porygon introduces a skills system that lets the agent extend its capabilities through Markdown files with YAML frontmatter (`name`, `description`) stored under `porygon/skills/` in the vault. Bundled skills shipped with the plugin are copied into the vault on first launch, parsed once at startup via a new `SkillsService` (after `onLayoutReady` so the vault is fully scanned) and cached, refreshing only when vault create/modify/delete/rename events touch the skills folder. The list is injected into the system prompt as an `<available_skills>` block, and a new `load_skill` agent tool reads the full skill body (without frontmatter) on demand using the exact location advertised in that block.

## 0.3.2: Expanded vault organization and graph agent tools
Porygon adds four vault-aware agent tools: `create_folder` for creating folders with Obsidian `Vault.createFolder`, `copy` for duplicating files or folders with `Vault.copy`, `active_file` for resolving the currently focused Obsidian file when users refer to “this note,” and `backlinks` for listing notes that link to a target note from Obsidian `MetadataCache.resolvedLinks`. These tools extend the assistant from note search/editing into vault organization and graph-aware navigation while preserving exact path validation, no filename guessing, and JSON tool results for transparent agent behavior.

## 0.3.1: Accurate RAG index counters and startup hardening
Porygon fixes a startup double-counting bug in the semantic index, prevents re-embedding of unchanged notes on launch and on stray re-enqueues, and makes the settings status row always reflect the real number of indexed and total notes.

## 0.3.0: Local semantic search over the vault
Porygon adds a local RAG foundation for semantic vault search using the same Ollama provider as chat: Markdown notes are chunked with LangChain text splitters, embedded with the configured Ollama embeddings model, and persisted in an IndexedDB-backed index under `src/rag/*`. The index is maintained in the background through startup reconciliation and Obsidian vault create/modify/delete/rename events, supports ignored-path settings and model/host freshness checks, exposes index status in settings, and adds a `semantic_search` agent tool that returns matching note paths, wikilinks, scores, and snippets for contextual note discovery while keeping existing exact `list`, `search`, and `view` tools as fallbacks.

## 0.2.7, 0.2.8, 0.2.9: Saved sessions and mention-aware reloads
Porygon added a `/sessions` command for loading saved chats from `porygon/sessions/`, renamed saved conversations to sessions, and changed `/save` to write `{session-id}.md` files with top-level metadata containing the session id and title. Session files now preserve per-message mention metadata in compact `kind`/`path`/`files` blocks so note and folder mentions can be rehydrated in order when a session is loaded; loading a session prompts to save the active chat first, restores visible messages and hidden file context, and logs malformed or missing mention data without blocking the load. Untitled sessions now generate a concise human-readable title from user messages through a lightweight LangChain/Ollama title generator, with a local fallback if generation fails.
